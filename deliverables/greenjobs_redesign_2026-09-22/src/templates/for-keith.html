What was built

  • Two editions, one codebase. greenjobs.ie and greenjobs.co.uk render from the same templates and scripts with their own data, currency and map. The edition switch keeps you on the same page.
  • Real data only. {{n_jobs}} live roles from {{n_emp}} employers, {{n_sectors}} sectors with roles, {{n_regions}} map regions with counts, {{n_sal}} disclosed salaries. Every job page links to the real listing. No invented testimonials, prices or audience numbers.
  • Search that answers instantly. Type-ahead on the home page, a filter rail with every state in the URL, list / map / saved views, a command palette (Ctrl+K), and per-job pages with JobPosting structured data so every role is eligible for job-search listings.
  • A sector taxonomy that means something. The demo derives {{n_sectors}} sectors with live roles from what each description says, and never shows an empty one, so every sector link a candidate clicks has work behind it.
  • Maps from real geometry. Natural Earth admin-1 boundaries merged into the 26 counties and 12 UK regions at build time, rendered as keyboard-operable buttons.
  • Salary explorer, career compass, "Ask GreenJobs". Charts drawn in-house (no library), a seven-question deterministic quiz whose result is a shareable link, and a smart-match panel that today runs entirely in the browser.
  • Zero third-party requests. Fonts are self-hosted; there is no analytics, no CDN, no framework, no build-time packages. Light and dark themes, reduced-motion fallbacks, WCAG 2.2 AA contrast, 44 px targets, print stylesheet on job pages.
  • A KPI dashboard and an event layer. /dashboard/ computes live board metrics from the listings at build time and lists the event spec for launch; every apply link, search, sign-up, rate request, post-a-job and save button already carries the event attribute, gated behind the cookie Analytics toggle, so the day a provider is connected the numbers start.

What changed since the first cut

  • A light opening. The home page opens on the living-landscape hero: one headline, the plain-English sub-line, the central search (what job, where), live credibility markers, a large "Post a job" beside "Find a job" and the B Corp mark with its explainer. The pinned map-pay-sectors film from the first cut was replaced after your 28 September notes by one compact "Salary insight" band (disclosed-salary share and median, sectors with live work, {{n_regions_unit}} map link).
  • "Quick job match." On the jobs page: paste a CV or three words and the six closest live roles appear instantly, with the matched words, your position on the board's disclosed-salary strip, a small map of where the matches are, and a caveat. The matcher is the upgraded local one (title-weighted, two-word phrases, sector and place boosts). Every result is a link you can share.
  • The live ad builder. On the Employers page the form renders the exact job card and job-page header as you type, previews a logo without uploading it, and reads reach from this week's data (live roles and median disclosed salary in the chosen sector). Sending still posts nothing and says so.
  • "Where this role sits." Every job page with a published salary shows that range against the board's disclosed distribution, overall and in its sector, with keyboard-reachable marks and a table; roles without one get an honest line with the sector's disclosed range instead. Both show how many similar roles are live in the same {{n_regions_unit}}.
  • Motion that explains. Numbers count up as they come into view, sparklines draw in, the map colours in region by region, a job title morphs from card to page and back, a thin bar in the header shows how far down you are. All of it is off under reduced motion and none of it moves layout.

Proposed for phase two

  • Run the board from one place. The demo already renders every page from a single data file; the next step is a small admin that writes that file, with a nightly build and deploy. The team edits once and both editions update.
  • Applicant tracking. Apply-in-place with a per-employer inbox, status changes and email notifications, replacing the redirect to a third-party form.
  • Employer self-serve. The "Post a job" preview on the Employers page becomes real: draft, preview, pay, publish, with the posting distributed across the network sites as today.
  • Model-backed assistant (optional, last). "Ask GreenJobs" keeps its interface and its contract (a query in, ranked role IDs and a one-line "why" out); the local matcher is swapped for a hosted language model behind a small server function with the key held server-side. The function stub, prompt contract and rate limit are already written; the cost model is in the technical appendix.

Technical appendix
  • Stack comparison. The live boards run on a hosted platform from the early 2010s (jQuery 1.11, Bootstrap 3, IE8 shims, classic ASP), which is why the before-and-after table above looks the way it does. The demo is static HTML, one stylesheet and a few small scripts, built by a Python script from JSON; free static hosting is sufficient at this size.
  • Structured data. The live job pages disable JobPosting markup ("Invalid salary data, so Google Schema is disabled" appears in their source); every demo job page emits valid JobPosting JSON-LD with the currency it was advertised in.
  • Assistant cost model. A query sends the question plus the compact live dataset (about {{n_jobs}} roles at roughly 120 tokens each, so about 12k tokens) and returns about 300 tokens. Multiply (12.3k input + 0.3k output) by the chosen vendor's per-token rate on launch day, then by 1,000, for the cost per 1,000 queries; cache the dataset portion so repeat queries within the cache window bill only the question. The rate is not quoted here to avoid publishing a stale number.
  • Weekly refresh. Scrape, build, validate, test, deploy; the build refuses a snapshot that drops more than 30% of roles and alerts the maintainer, not GreenJobs.

Notes on honesty

  • Sector tags, region matches and annualised salaries are derived from the listing text by rules that are in the build script; they can be wrong on individual roles and are labelled as derived where they appear.
  • The "Why GreenJobs" facts, the employer offer and the B Corp mark come from your own pages as fetched on 2026-09-22 (brief.md). The demo shows the mark in the hero, the header and the footer with its alt text and a generic one-line definition of B Corp; it adds no certification date, score or other claim. Confirming current status and logo permissions is on the launch checklist above.
  • Newsletter, alert and post-a-job forms send nothing and say so.
  • Job descriptions are shown as published by employers (sanitised of scripts and styles); the word-filter that keeps machine vocabulary off the public pages does not apply inside them.
