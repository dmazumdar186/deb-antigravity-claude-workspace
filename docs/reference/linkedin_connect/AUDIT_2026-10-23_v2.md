# LinkedIn Connect Daily — audit v2 (2026-10-23, after first live run and architecture change)

Scope: `execution/personal_workflows/linkedin_connect_queue.py` (lock, health, sync, aliases added), `directives/personal_workflows/linkedin_connect_daily.md` (slots + guardrails + failure matrix), `.claude/skills/linkedin-connect/SKILL.md`, Drive folder `linkedin_connect`, cloud trigger "LinkedIn connect: Drive ledger reconcile" (21:27 Europe/Paris).
Method: live-run report review (14 sent); adversarial reading of the new scheduling model (8 slots/day, unpredictable login time and time zone); 24-case eval through the real CLI, run twice, identical md5 724e94e9; health invariants run on the real state.

## 1. Architecture (what runs where, and why)

| Layer | Where | Why there |
|---|---|---|
| Clicking Connect | Operator's PC, logged-in Chrome, Cowork | Only place LinkedIn sees the real user; cloud IPs trip checkpoints |
| Trigger | 8 Cowork slots/day, machine-local time | "Run when I log in" without a login hook: first slot after login works, later slots no-op |
| Bookkeeping | Deterministic Python, no LLM in the loop | Cap, dedupe, lock, health are code, not judgement |
| Truth for state | Google Drive folder (ledger snapshots, aliases) | Public repo cannot hold PII; Cowork shell has no git credential; survives local loss |
| Prospect list | Rebuilt locally from the operator's CSVs each run | Static, large, stays off the public repo; new CSVs join automatically |
| Reporting | Gmail to operator, four fields + ledger block | Human-readable and machine-recoverable in one artefact |
| Day-end assurance | Cloud trigger into the building session | Turns a silent day into a one-line message; reconciles Drive from email if needed |

## 2. Gaps found and fixed in v2

| # | Gap | Impact if unfixed | Fix | Eval |
|---|---|---|---|---|
| V1 | Fixed 08:00 schedule; PC not logged in → day lost | Frequent zero days | 8 idempotent slots/day; first after login does the work | directive |
| V2 | Two slots could overlap on a long run | Double sends | Run lock, exit 4, 120-min stale takeover | 23 |
| V3 | No pre-send invariant check | Sends on corrupted state | `health` gate: 7 invariants, exit 1, no sends until HEALTHY | 24 |
| V4 | Email-required dialog treated as stop | Lost 10 sends on day 1 | Skip + continue | directive |
| V5 | Slug redirects could re-add a person from a fresh export | Duplicate request | aliases.csv + `--canonical` | 21 |
| V6 | Ledger only in git; Cowork cannot push | State lost between runs | Drive snapshots + `sync` union; report carries ledger block | 22 |
| V7 | Dataset committed to a public repo | PII exposure | Removed from tree, gitignored; history rewrite declined by operator (repo stays public) | n/a |
| V8 | Local `data/` deleted by a branch switch during this audit | Would have been a zero-send day with no master | Caught by `health` master_present; rebuilt byte-identically from uploads + Drive + report in one command | 24, live |

## 3. Residual risks

| # | Risk | Likelihood | Mitigation |
|---|---|---|---|
| R1 | LinkedIn restricts the account (ToS) | Medium over months | 25/day, 45–120 s gaps, stop on warnings, acceptance-rate throttle; no concealment |
| R2 | PC never logged in on a day | Depends on operator | Not fixable by software; 21:27 check reports it; queue resumes next login |
| R3 | Cowork lacks the Drive connector | Unknown until first slot run | Email ledger block fallback; cloud task uploads to Drive |
| R4 | Cowork scheduled tasks do not fire while the app is closed | Medium | 8 slots; operator keeps the Claude app open at login (autostart) |
| R5 | Old dataset commits remain in public history | Certain (operator decision) | Documented; purge available on request |
