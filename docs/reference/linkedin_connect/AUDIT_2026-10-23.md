# LinkedIn Connect Daily — audit, vulnerability test, eval (2026-10-23)

Scope: `execution/personal_workflows/linkedin_connect_queue.py`, `directives/personal_workflows/linkedin_connect_daily.md`, `.claude/skills/linkedin-connect/SKILL.md`, dataset `data/linkedin_connect/master.csv`.
Method: line-by-line read of the script against the directive's contract; adversarial inputs (bad columns, encodings, URL shapes, cap breaches, cross-day state); 20-case eval through the real CLI, run twice (identical md5 a73f3fc2).

## 1. Gaps found and fixed

| # | Gap / vulnerability | Impact if unfixed | Fix | Eval |
|---|---|---|---|---|
| G1 | URL column chosen by header alias; an Apollo export has `Company Website`, `Company Linkedin` and `LinkedIn` | Wrong column → every row "no URL", or company pages queued | Column picked by content (most values containing `linkedin.com/in/`) | 6 |
| G2 | CSV read as UTF-8 only | Excel cp1252 export crashes consolidate | utf-8-sig → cp1252 → latin-1 fallback | 7 |
| G3 | Percent-encoded slugs kept raw | Same person counted twice (`jos%C3%A9` vs `josé`) | `unquote` + lowercase | 4 |
| G4 | `/company/`, `/pub/`, Sales Navigator URLs accepted as slugs | Cowork opens a non-profile page, wastes a slot | Rejected, counted as "no URL" | 5 |
| G5 | Queue frozen once written; skips never backfilled | A day with 10 already-connected people sends only 15 | Top-up to the remaining room on every `plan` | 14 |
| G6 | Directive said "retry later" but every status was terminal | Unconfirmed clicks lost forever | New non-terminal `retry` status: out today, eligible tomorrow | 13 |
| G7 | `--limit 0` wrote an empty queue that blocked the day | Silent zero-send day | Rejected with exit 2 | 10 |
| G8 | Shuffle was a directive instruction to the LLM | Non-reproducible order, no audit trail | `plan --shuffle`, seeded by date | 18 |
| G9 | Ledger rows for slugs not in master went unnoticed | Hand edits or a master rebuild could hide double-sends | `status` warns on orphans and bad statuses | 17 |
| G10 | State in gitignored `.tmp/` | Ledger lost between machines → duplicate requests | Data dir `data/linkedin_connect/`, repo-tracked; pull before / push after each run | directive |
| G11 | Eval harness wrote fixtures into a missing dir (found when 18/20 failed on first run) | False FAIL on every case | Harness creates the dir | all |

Confirmed already correct, kept: 25/day hard cap refuses the 26th (exit 3); duplicate terminal mark refused; weekly soft cap 100 trims the day; report carries exactly name, company, position, LinkedIn ID; idempotent re-consolidate.

## 2. Residual risks (not fixable in code here)

| # | Risk | Likelihood | Mitigation in place |
|---|---|---|---|
| R1 | LinkedIn restricts the account for automated invitations (ToS) | Medium over months at 25/day; low per day | Pace 45–120 s, hard stop on captcha/limit/restriction text, no concealment, acceptance-rate check (<25 % → cut to 15/day) |
| R2 | Browser step misreads a button state (Connect vs Follow vs Pending) | Medium on first runs | Watch the first 5 profiles live; unconfirmed → `retry`, never `sent` |
| R3 | Two machines run the same day without pulling | Low | Directive mandates pull/push; `status` orphan check; ledger is append-only |
| R4 | Profile slug redirects (person renamed URL) | Low | Queue keeps original slug; mark by queue slug |
| R5 | Cowork scheduled task does not fire (machine asleep) | Medium | Same-day re-run is idempotent; missed days are not back-filled on purpose |
