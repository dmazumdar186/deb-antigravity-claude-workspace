## 1. What slipped and why

| # | Defect | Where it came from | Why it was not caught |
|---|---|---|---|
| D1 | ```ledger CSV block in the email | v2 audit 2026-10-23 (V3 "Drive unavailable" fallback): the report file was reused as a state-transport so the ledger could be rebuilt from the inbox | The eval (c16) only checked the table rows; it never asserted "nothing else". The directive's contract line was rewritten to describe the new output instead of being treated as fixed. |
| D2 | Status paragraph ("this slot found…", "8122 remaining") | Runbook step 6 "one line to the operator" was ambiguous about channel; the slot agent folded it into the email | No instruction said "email body = table only"; nothing in the eval covers agent prose |
| D3 | Eight slots/day burning the usage pool | v2 audit V1: "unpredictable login hour" solved by slot density instead of by asking the operator | Schedule chosen by the auditor, never confirmed with the operator; five of 2026-10-25's runs died on `USAGE_LIMIT_REACHED` |

Pattern across projects: during a *hardening* pass, a convenient mechanism (a fallback transport, a denser schedule) gets attached to a human-facing artefact because the same file or task is already there. The product contract is not written down as a test, so the diff looks like an improvement. The rule promoted to CLAUDE.md principle 7: a deliverable's fields, shape, channel and cadence are a contract; machine state gets its own channel; changing either needs the operator's word, and an audit is not that word.
