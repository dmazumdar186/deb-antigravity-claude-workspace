## 1. How Max usage is metered

- Pro/Max meter a rolling 5-hour session plus a weekly limit "across all models"; Claude and Claude Code share one pool (https://support.claude.com/en/articles/11049741-what-is-the-max-plan, https://support.claude.com/en/articles/11145838).
- What consumes usage: "message length, attachment size, conversation length, tool usage, model choice, effort level, multi-step tasks" (https://support.claude.com/en/articles/9797557-usage-limit-best-practices). Per-model weighting factors are **not published**; the only official hint is model-specific limit messages ("You've hit your Opus limit") and "switching to a model outside that family keeps the developer working" (https://code.claude.com/docs/en/costs#when-a-developer-asks-about-a-limit). The "Fable ≈ 5x Sonnet" figure in `token-economy.md` is unsourced — treat as operator inference.
- Cache reads: Claude Code "re-reads that history at the cached token rate, so a one-line question in a session open all day still draws usage for the whole conversation" — cached tokens count, at a discount, and a cache miss after >1h idle reprocesses full context (https://code.claude.com/docs/en/costs#why-usage-climbs-in-a-long-session). Exact discount against the subscription cap: unknown.
- Sub-agents, workflows and teammates all count: "Runs count toward your plan's usage and rate limits" (https://code.claude.com/docs/en/workflows#cost); teams "use significantly more tokens… roughly proportional to team size", ~7x in plan mode (https://code.claude.com/docs/en/costs#agent-team-token-costs). `/usage` attributes plan usage to skills, subagents, plugins, MCP servers, and flags "long context" / "cache misses" when ≥10% (https://code.claude.com/docs/en/costs#plan-usage-breakdown).

## 3. Teams vs sub-agents vs workflows

- Orchestrator context: sub-agent returns only its final text + a token trailer (docs example: 6,100 tokens read → 420-token result, https://code.claude.com/docs/en/context-window); workflow keeps intermediate results in script variables so "Claude's context holds only the final answer" (least of all); teams keep each teammate's context separate but every idle notification/message lands in the lead, and teams are "Higher: each teammate is a separate Claude instance" vs sub-agents "Lower" (https://code.claude.com/docs/en/agent-teams#compare-with-subagents).
- Anthropic's recommended split: orchestrator-worker, "scale effort to query complexity" (1 agent/3-10 calls for simple, 2-4 agents for comparisons), subagents store work externally and pass "lightweight references", and note multi-agent ≈15x chat tokens (https://www.anthropic.com/engineering/multi-agent-research-system). Best-practices: explore/plan in plan mode, write a spec then start a fresh session, `/clear` after two failed corrections, sub-agents for investigation and adversarial review, `/batch` or `claude -p` loops for fan-out (https://code.claude.com/docs/en/best-practices).

## 4. Ranked recommendations for this repo

1. Cut always-loaded prefix: CLAUDE.md to ≤7k (it is 8,011); give `automation-boundaries.md` and `testing.md`/`python-execution.md` `paths:` frontmatter; fold `always-parallelize` into token-economy. Every byte is re-sent on every call of main + every sub-agent (they load CLAUDE.md + rules too). ~3-4k tokens/call.
2. Set `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=0` unless a team is wanted that session: with `1`, any subagent Claude names launches as a full teammate (own CLAUDE.md/MCP/skills load, no summary-only return) — an invisible cost multiplier (https://code.claude.com/docs/en/agent-teams#claude-spawns-teammates-instead-of-subagents).
3. Trim skill descriptions (13.3k chars ≈ 3-4k tokens per call) and add `disable-model-invocation: true` to operator-only skills (wework-booking, welcome-email, job-digest, etc.) so their descriptions drop out of context.
4. Add `effort: low` to mechanical agents (documenter, note-taker, email-classifier, qa) and `omitClaudeMd: true` where the delegation prompt is self-contained; add `maxTurns`. Since workers are now Fable 5.1, effort is the main remaining dial there.
5. Hooks: `session-start.sh` is fine (small). PostToolUse `note-taker.sh`/`documenter-prompt.sh` stdout is discarded on exit 0 — they cost nothing but also do nothing; delete or convert to a Stop-hook exit-2 check. No wasteful env entries; `teammateMode` is harmless.
6. Session hygiene per costs page: `/clear` between tasks, `/compact` at breaks, avoid >1h idle then resuming a big session (cache miss), use `/rewind` over compact, `/btw` for side questions; keep `run_in_background` (not a poll loop) — polling turns each re-send full context.
7. MCP: `.mcp.json` firecrawl+tavily are deferred already; prefer `curl`/`gh`; remove servers unused for a month (`/usage` attribution shows share).
8. Prefer `ultracode:` workflows over teams for >5-unit fan-out (`workflowSizeGuideline: small|medium`); set `subagentPromptCacheTtl: 1h` only for long fan-outs (higher write rate).
9. Set `autoMemoryEnabled: false` if MEMORY.md is not curated (up to 25KB/session); or curate it.
10. `awaySummaryEnabled: false`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` on local machine (small but free).

## 5. Not real / not allowed

- Account or credential sharing, selling access: prohibited ("You may not share your Account login information… or make your Account available to anyone else", https://www.anthropic.com/legal/consumer-terms). Anthropic's weekly limits were introduced specifically against sharing/reselling and 24/7 background runs (https://techcrunch.com/2025/07/28/anthropic-unveils-new-rate-limits-to-curb-claude-code-power-users/).
- Multiple Max accounts: a Claude Code team member said it is "not against terms of service", but the AUP bans coordinating across accounts to circumvent guardrails or bans (https://www.anthropic.com/legal/aup; https://github.com/anthropics/claude-code/issues/54464). Anthropic has also stated it may "limit your usage in other ways… at our discretion" (Max plan article). Not a strategy to build on.
- Non-API automated access outside Claude Code is prohibited by the consumer terms; proxies/gateways that strip `cache_control` make usage worse, not better (prompt-caching page). `DISABLE_PROMPT_CACHING` increases cost. `/insights` bills tokens. There is no setting that makes cached or sub-agent tokens free; usage credits (`/usage-credits`) are the only official overflow path.
