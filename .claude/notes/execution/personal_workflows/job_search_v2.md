# Notes

- [learned] Sheet duplicates root cause: STANDARD_HEADERS had been trimmed to 6 columns (no `_id`), so the in-sheet `_id` dedup was silently a no-op ("appending without dedup" warning), and seen.db is lost on GH-Actions cache misses. Fix: title+company fingerprint (`contracts.compute_fingerprint`) merged in-batch, in seen.db, and across all role tabs at append (id / canonical Link / fingerprint). Live 2026-09-10: 565 source jobs → 424 after in-batch merge (141 cross-source dupes).
- [learned] Freshness: source `posted_at` is unreliable — WTTJ Algolia gives the UPDATED date and LinkedIn cards show the REPOST date; the job page's JSON-LD `datePosted` / `<time datetime>` is days-to-months earlier. Stage 3.8 `posting_verifier` reads the page and the page date wins. 13 of 148 live jobs dropped as stale on first run.
- [technical] Board quirks: WTTJ anti-bot answers HTTP 202 + empty body (retry once after 3 s fixes most; treat empty 2xx as unverifiable, never as "no signal"); WTTJ soft-404 = HTTP 200 with "Error 404 Page not found" in the body; LinkedIn expired jobs 200-redirect to `/jobs/<slug>-jobs?trk=expired_jd_redirect`; LinkedIn 429 on ~3% of fetches at concurrency 8; weworkremotely.com returns 403 to every page fetch (rows kept on the feed's pubDate, stamped "unverified (source date)").
- [learned] Domain filter tuning from live data: profile `skip_domain_anchors` overlap built-in anchors, so one "medical device" mention counted as two distinct hits and rejected a Software-as-a-Medical-Device role — count distinct MATCHED TEXT, not anchor names. "instrumentation", "optics", "sensor", "mechanical", "battery", "RF", "kernel" are software vocabulary in descriptions (Proton "Senior PM (Inbox)" false positive) — excluded from description counting, title-only. Ambiguous anchor + software-product word in the same title ("Sensor Data Platform") is rescued.
- [pattern] Every sheet row now carries a `Verified` stamp (`open · posted YYYY-MM-DD · checked YYYY-MM-DD`); the acceptance gate parses it and fails stale-at-insert (> 7 d), closed, undated or unstamped rows, and fails any live run whose stats show verification skipped. Historical unstamped rows are re-verified by `purge_irrelevant_rows.reverify_rows` (400 fetches/run budget).
- [technical] `verify_jobs` wraps each worker in try/except (an exception in one page fetch would otherwise kill the cron); future page dates (> now + 1 day) are ignored in favour of the source date.
- [constraint] Sub-agents in this cloud session were killed twice by the account usage limit (Fable auditor + Sonnet workers); resume by re-spawning with "continue from the partial file" instructions — partial test files survived on disk.
- [constraint] This sandbox cannot import gspread (`_cffi_backend` / cryptography panic) or pdfplumber; tests stub `gspread` in `sys.modules`; langdetect has no wheel for Python 3.11 here (language filter defaults to accept locally — CI installs it fine).
